# Sigelith Hourglass - formats and algorithms (v1)

Status: **v1**, 2026-11-23. This specification becomes binding with the first v1 genesis; from
then on the v1 formats never change (a change means new identifiers). Phase 0 (identifiers `p0`,
2026-10-19 to 2026-11-18) used the same construction without the v1 additions listed in §13; its
data stays verifiable with the same code. This is the public English version of the operator's
specification; the executable form is `reference/hourglass_ref.py` (Python, standard library
only). Test vectors: `vectors/vectors.json` (generated by `reference/gen_vectors.py`). Tests:
`python -I -m unittest discover -s tests -v`. The production prover must produce the same bytes
as the reference implementation.

**Hourglass is a proof of sequential work (PoSW) after Cohen and Pietrzak, not a VDF.** A VDF
from hash functions alone does not exist in the random-oracle model (Guan, Riazanov, Yuan,
CRYPTO 2025; Abusalah et al., EUROCRYPT 2026); the absence of a unique output and the
coefficient c (§6) are the price of any construction built from hashes only.

---

## 0. Glossary

| term | meaning |
| --- | --- |
| clock | one chain of segments from one genesis, run by one operator (`operator`, §7) |
| segment j | one hash tree computed from the seed χ_j; j = 1, 2, 3, … |
| n | depth of the segment tree; 2ⁿ leaves, N = 2ⁿ⁺¹ − 1 nodes |
| ℓ_v | label of node v (32-byte SHA-256) |
| φ_j | root of segment j (= the root's label); φ_0 is the genesis root |
| χ_j | seed of segment j |
| t, γ_i | number of checks and the checked leaves (Fiat-Shamir) |
| π_j | proof of segment j (file `<j>.proof`) |
| λ | security level in bits, with a margin for grinding (§6) |
| c | share of the steps guaranteed by the checks (`claim_permille`) |
| k | the explicit assumption about hardware advantage: no one computes this more than k times faster than the reference speed |
| s_ref, s_eff | the reference speed common to all clocks (nodes/s), and the speed a segment is counted with: the larger of s_ref and the segment's own highest speed (§10) |

## 1. Constants, tags, identifiers

- Hash function: SHA-256 (FIPS 180-4). Labels and digests: 32 raw bytes; in JSON, 64 lowercase
  hex characters.
- Version tag: `p0` (phase 0) or `v1`. Prefix P: `sigelith-hourglass-p0` / `sigelith-hourglass-v1`.
- Domain separators (ASCII bytes): `P|node|`, `P|challenge|`, `P|seed|`, `P|genesis|`.
- Format identifiers: p0 `sigelith-hourglass-p0-genesis`, `sigelith-hourglass-p0-segment`;
  v1 `sigelith-hourglass-genesis-v1`, `sigelith-hourglass-segment-v1`.
- Record signature (v1, §8): Ed25519 (RFC 8032) over `sigelith-hourglass-segment-v1|` ‖
  JCS(record without `sig`), like the Sigelith receipt `sigelith-receipt-v1`. This domain and
  the other Sigelith domains (`sigelith-receipt-v1|`, `beattime-proof-v1|`,
  `beattime-checkpoint-v1|`, `sigelith-cosign-v1|`) are disjoint: none is a prefix of another.
  Keys and signatures in JSON: canonical base64 (RFC 4648, with padding) of 32 and 64 bytes.
- Ranges: 1 ≤ n ≤ 48, 1 ≤ t ≤ 1024, 1 ≤ λ ≤ 256.

## 2. Segment graph

- Node v = (d, b): depth d (0 … n) and the value b of its d bits (first bit most significant).
  Root = (0, 0). Children of (d, b): (d+1, 2b) and (d+1, 2b+1). Leaf u = (n, u).
- Edges: every child → its parent; and for every leaf u and every i = 1 … n where the i-th bit
  of u is 1: an edge from node (i, (u ≫ (n−i)) − 1), the left sibling of the node on the path to
  u at depth i.
- **Parents:** of an internal node (d, b): (d+1, 2b), (d+1, 2b+1) in this order; of a leaf u:
  the left siblings on its path, from the root down (increasing i).

## 3. Node label

```
enc(d, b) = 1 byte d ‖ BE64(b)                                  (9 bytes)
ℓ_v       = SHA-256( P|node| ‖ χ ‖ enc(v) ‖ ℓ_p1 ‖ … ‖ ℓ_pm ‖ 0^(32·(M − m)) ),   M = max(2, n)
```

- The input has **one fixed length for all nodes** of a segment: L = |P|node|| + 32 + 9 + 32·M
  (for n = 32: 1092 bytes, 18 SHA-256 blocks; for n ≤ 32 the first block depends only on the
  node's depth, so a prover computes its state once per depth and then 17 blocks per node).
  Every call therefore costs the same number of compressions, and the proven time follows from
  the average speed.
- Zeros pad the input **at the end**. A constant prefix could be computed once for many nodes.
- The number of parents follows from v (the verifier knows it), so the padding is unambiguous.
  The depth in enc(v) distinguishes leaves from internal nodes.

## 4. Order of computation (post-order with a stack)

```
stack ← []
for u = 0 … 2ⁿ − 1:
    ℓ ← label(leaf u, parents = labels on the stack, bottom to top)
    push (n, u, ℓ)
    while the two top entries have the same depth d:
        pop the right (d, ·, r) and the left (d, b, l); push (d − 1, b ≫ 1, label(node, [l, r]))
φ ← the single entry left on the stack (depth 0)
```

- Before each leaf the stack holds **exactly** its parents, from the root down. Every node depends
  on the previous one, so this is one sequential path through all N nodes. Memory: O(n) labels.
- **Answering checks without the whole tree:** the prover keeps the top levels 0 … n − m and, for
  a check, recomputes the subtree of 2^(m+1) − 1 nodes below the leaf's ancestor at depth n − m,
  starting from the labels of the left siblings on the path to that ancestor (`subtree()` in the
  reference implementation). Subtrees are independent; the prover computes them in a separate
  thread.

## 5. Checks, proof, verification

```
γ_i = first n bits of SHA-256( P|challenge| ‖ χ ‖ φ ‖ BE32(i) ),   i = 1 … t
```

- γ_i does not depend on t, so **the proof for t is a prefix of the proof for a larger t**: the
  first t' checks of a proof (its first t' · n · 32 bytes) are the proof for t'. A verifier may
  check only such a prefix (§10.1).
- **Proof π:** for i = 1 … t in turn: the labels of the siblings of the nodes on the path from leaf
  γ_i to the root, at depth n, n − 1, …, 1. In total t · n · 32 raw bytes, no header. The leaf
  label is not included: the verifier computes it from the leaf's parents (the left siblings
  contained in the proof).
- **Verification** of each check: (1) the leaf label from its parents; (2) up the path: parent =
  label(node, [left, right]), one child being the current label and the other the sibling from
  the proof; (3) the result equals φ. Cost: t · (n + 1) SHA-256 calls (n = 32, t = 256: about
  50 ms in Python).

## 6. Guarantee, λ and c

- Cohen-Pietrzak: whoever made fewer than (1 − α) · N sequential calls passes t independent
  checks with probability at most (1 − α)ᵗ (plus a negligible term for 256-bit labels). The exact
  statement and constants for the Fiat-Shamir version are **to be confirmed against the papers**
  (Cohen, Pietrzak, EUROCRYPT 2018; quantum: Blocki, Lee, Zhou 2021; Chung, Fehr, Huang, Liao,
  EUROCRYPT 2021).
- **Grinding the root is cheap.** With Fiat-Shamir, a cheater who computed part of the tree can
  change a "junk" leaf at the end and get a new root, and with it new checks, for about n hashes
  per attempt, in parallel. The success chance grows linearly with the number of attempts q:
  ≈ q · (1 − α)ᵗ (demonstrated by the test `test_grinding_the_root_is_cheap`). Therefore
  **λ = λ_target + log₂ q_max**; by default 40 + 60 = **100** (a margin for 2⁶⁰ attempts within one
  segment).
- `claim_permille` = the largest p ∈ [0, 1000] with pᵗ · 2^λ ≤ 1000ᵗ, in integers. A record claims
  only c · N steps of its segment.

| t | λ | c (‰) | proof at n = 32 |
| --- | --- | --- | --- |
| 64 | 40 | 648 | 64 KB |
| 128 | 100 | 581 | 128 KB |
| 256 | 100 | **762** | 256 KB |
| 512 | 100 | 873 | 512 KB |

- **v1 parameters** (the ones phase 0 measured): n = 32 (a segment of about 2 hours on the
  Sigelith server), t = 256, λ = 100, c = 0.762. A full proof of age for one year is about 1.2 GB
  (about 4,500 segments of 256 KiB); a proof of a requested age is much smaller (§10.1).

## 7. Canonical JSON, genesis, inputs, seed

- Canonical JSON: the same subset of JCS (RFC 8785) as Sigelith checkpoints: ASCII keys, integers
  only with |x| < 2⁵³, strings without control characters, UTF-8, sorted keys, no spaces, no
  trailing newline.
- Time: `canonical_utc`, i.e. `YYYY-MM-DDTHH:MM:SS.ffffffZ` (always six fraction digits and `Z`),
  as in the log.

**Genesis**, exactly these fields:

| field | content |
| --- | --- |
| `v` | `sigelith-hourglass-genesis-v1` (p0: `sigelith-hourglass-p0-genesis`) |
| `operator` | v1 only: the identifier of the clock's operator, by convention its domain name (`sigelith.org`): 1 to 64 characters from `a-z`, `0-9`, `.`, `-`, the first and the last a letter or a digit. Two clocks therefore never share a genesis, even with the same inputs |
| `hash` | `"sha-256"` |
| `n`, `t`, `lambda` | initial parameters (§1, §6) |
| `checkpoint` | `{"n", "sha256"}`: the latest `beattime-checkpoint-v1` (number and SHA-256 of the file) |
| `btc` | `{"height", "hash"}`: the newest known Bitcoin block |
| `utc` | `canonical_utc` of creation (server clock) |
| `k_assumed` | the assumed k (integer ≥ 1) |
| `s_ref_nodes_per_s` | v1 only: the reference speed at the start (§10) |
| `s_self_nodes_per_s` | p0 only: speed from the start-up benchmark |

```
φ_0 = SHA-256( P|genesis| ‖ JCS(genesis) )
x_j = SHA-256( JCS({"btc": {"hash", "height"}, "checkpoint": {"n", "sha256"}, "utc": <start of segment j>}) )
χ_j = SHA-256( P|seed| ‖ BE64(j) ‖ φ_{j−1} ‖ x_j )
```

- The genesis file is stamped in the log like any other file. It carries no signature: the first
  signed record of the clock contains φ_0 as `prev_root`.
- The inputs are the newest data at the start of the segment (older data only weakens the
  segment's own "not earlier than"). The prover stores the inputs and the seed durably before it
  starts computing.
- Every clock absorbs the latest Sigelith checkpoint, so an entry of the log gets into all clocks
  (§10.2).

## 8. Segment record and proof file

Record (`segments/<j>.json`, j with at least 6 digits), exactly these fields:

| field | content |
| --- | --- |
| `v` | `sigelith-hourglass-segment-v1` (p0: `sigelith-hourglass-p0-segment`) |
| `j`, `n`, `t`, `lambda` | segment number and its parameters (may differ between segments) |
| `prev_root` | φ_{j−1} (hex) |
| `inputs` | `{"btc", "checkpoint", "utc"}` from §7; `utc` = start of the segment |
| `seed`, `root` | χ_j and φ_j (hex) |
| `proof` | `{"file": "<j>.proof", "sha256": <SHA-256 of the file>}` |
| `utc_end` | end of the segment (`canonical_utc`) |
| `gaps` | list of interruptions `{"from_node", "utc_stop", "utc_resume", "reason"}` |
| `speed` | `{"nodes_per_s_min", "nodes_per_s_median", "nodes_per_s_max"}`, integers |
| `ptb_offset_us` | the latest offset of the server clock to PTB in µs, or `null` |
| `k_assumed` | the assumed k at the time of the segment |
| `s_ref_nodes_per_s` | v1 only: the reference speed at the time of the segment (§10) |
| `claim_permille` | = the formula of §6 for the segment's t and λ |
| `coverage_permille` | ⌊1000 · N · 10⁶ / (`nodes_per_s_max` · µs from `inputs.utc` to `utc_end`)⌋: information about the clock's operation, not part of the proof |
| `key` | v1 only: the operator's Ed25519 public key that signed the record (canonical base64, 32 bytes) |
| `sig` | v1 only: Ed25519 signature (canonical base64, 64 bytes) of `sigelith-hourglass-segment-v1|` ‖ JCS(record without `sig`) |

- File `<j>.proof`: the raw proof bytes of §5 (t · n · 32 bytes).
- Rules: `inputs.utc` ≥ `utc_end` of the previous segment (for j = 1: ≥ the genesis `utc`);
  `utc_end` > `inputs.utc`; `nodes_per_s_min` ≤ median ≤ max. There is no separate start field:
  the start is `inputs.utc` (it is in the seed).
- `gaps`: `from_node` = number of nodes computed before the interruption, in the order of §4; the
  prover resumes at leaf u, so `from_node` = 2u − popcount(u). `utc_stop` = the last durable state
  save before the interruption, `utc_resume` = the resumption. Reason: `restart` (the process or
  the machine stopped; the prover cannot tell which). An interruption changes neither labels nor
  the root; it only lowers `coverage_permille`.
- `speed`: speeds of consecutive computing windows of at least 1 s (nodes in the window / window
  time); min, median and max of these windows. A segment shorter than one window: one value =
  N / segment time.
- `ptb_offset_us`: the "System time" field of `chronyc -c tracking` in µs, read by the sync in the
  last minute before `utc_end`; **positive = the server clock is behind PTB**, negative = ahead
  (the sign chrony uses in CSV mode). Only when chrony follows a PTB time server (its source
  address among the DNS addresses of `ptbtime1…4.ptb.de`); with another source, no DNS, or no
  answer from chrony: `null`.
- **Signature and publication (v1).** The prover never holds a key: it writes the record without
  `key` and `sig`. The operator's publisher checks the segment (§9), adds `key` and `sig`, and
  publishes the record as JCS(record): exactly these bytes, without a trailing newline. The
  SHA-256 of these bytes is stamped in the Sigelith log, so the record gets a receipt and the
  log's anchors like any entry.
  - The Sigelith clock is published by the Sigelith server and signed with the log key.
  - Another operator signs with its own key, created on its own machine. It sends the signed
    record and the proof to Sigelith, which checks, stores, stamps and serves them like its own.
    Sigelith cannot forge such a record.
  - The signature says only "this operator published this record". The bound of §10 does not
    depend on it, and losing or replacing a key does not stop the clock.
  - A verifier checks `key` against the operator's published key history (for Sigelith:
    https://sigelith.org/spec/#keys), never against the record alone.
- In phase 0 records are not signed; each one is stamped in the log like any entry.

## 9. Checking the chain; forks

1. φ_0 from genesis; for j = 1, 2, …: `prev_root` = φ_{j−1}; χ_j recomputed from `prev_root` and
   `inputs` = `seed`; SHA-256 of the proof file = `proof.sha256`; the proof passes §5; the rules of
   §8; `claim_permille` and `coverage_permille` match their formulas.
2. Numbering continuous from 1, no holes.
3. v1: `key` is in the operator's key history and `sig` is valid. A verifier without the key
   history reports the signatures as not checked; the bound of §10 stays valid.
4. **Fork:** two different `root` or `seed` values for the same j, within one source or between
   sources (our publication, archived copies), are an incident, not an error to skip
   (`find_forks()`). In v1 two such records signed with the operator's key prove the fork against
   the operator.
5. Consistency outside the proof: record times against the times of the records' stamps in the
   log, confirmed by the cosigners. In v1 the cosigners check every new segment of every clock
   (milliseconds) and confirm that they saw it.

## 10. Elapsed time and minimum age (integers)

```
s_eff_s     = max( s_ref_nodes_per_s_s , nodes_per_s_max_s )
w_s         = ⌊ claim_s · N_s / (k_s · s_eff_s) ⌋                 milliseconds
Δ_min(A, B) = ⌊ (w_i + w_{i+1} + … + w_j) / 1000 ⌋                 seconds
```

- A was absorbed into the seed of segment i (directly or through a checkpoint,
  `absorbing_segment()`), B contains φ_j. Only complete segments i … j count.
- Every segment counts with the values of its own record: k_s = `k_assumed` and
  s_ref = `s_ref_nodes_per_s` hold at the time of computing; a later change applies only to new
  records. claim_s = claim_permille(t, λ) of the record, or claim_permille(t', λ) when only the
  first t' checks were verified (§10.1).
- **Minimum age** of an entry: the same with j = the newest published segment (the record of
  segment j is the file B).
- **The reference speed is common to all clocks:** 1,308,141 nodes/s in v1, the highest speed
  measured in phase 0 on the Sigelith server, to which k = 20 refers (technical note no. 1,
  https://doi.org/10.5281/zenodo.24460343). A slower clock counts with s_ref and cannot inflate
  its bound; a faster clock counts with its own highest speed (s_eff).
- Example (v1 parameters, k = 20): one segment guarantees w = ⌊762 · (2³³ − 1) / (20 · 1,308,141)⌋
  = 250,184 ms. For n = 32 every intermediate value stays below 2⁵³.
- Every result carries its assumptions: the clock, k, c (t, λ), s_ref and the segments counted
  with a higher s_eff, n, the range of segments.
- Phase 0 records have no `s_ref_nodes_per_s`; for them Δ_min = ⌊ Σ claim_s · N_s /
  (1000 · k · s_max) ⌋ with s_max = the highest of `s_self_nodes_per_s` and all `nodes_per_s_max`
  (`min_elapsed_seconds()`).

### 10.1 Proof of a requested age (proof prefixes)

- The full proof of age of an entry is all records i … j with their proofs: about 1.2 GB for a
  year with the v1 parameters. Usually much less is needed.
- A verifier may check, for any segment, only the first t' checks of its proof (1 ≤ t' ≤ t, the
  first t' · n · 32 bytes, §5). The segment then counts with claim_permille(t', λ); at λ = 100
  this is zero for t' ≤ 10.
- **Every segment i … j needs at least one check.** A check opens a leaf whose label depends on
  the seed, so the root was computed after the seed existed; the seed of the next segment
  contains that root, so the order of all segments holds. A segment with no check at all would
  break the chain: the segments before it and after it could have been computed in parallel.
- For a prefix the verifier cannot compare `proof.sha256` (the hash of the whole file); it checks
  the prefix directly against the record's seed and root. The formats do not change.
- Example: an entry from a year ago, "at least one day": 346 full proofs (86.5 MiB) and about
  4,100 one-check prefixes (1 KiB each, 4 MiB) plus the records, about 100 MB in total instead
  of about 1.2 GB.
- Reference: `python -I reference/hourglass_ref.py age <directory>` takes the records i … j
  without the genesis and accepts proof prefixes.

### 10.2 Several clocks

- Each clock (one genesis, one operator) is checked on its own. An entry absorbed into several
  clocks has as its minimum age the maximum of their bounds, each valid on its own (the entry
  absorbed in that clock, B containing that clock's root). A pause of one clock is covered by the
  others; a cheater would have to outrun all of them.
- All clocks count with the same s_ref (§10).

## 11. Test vectors (`vectors/vectors.json`)

- `chi`: a fixed test seed = SHA-256 of the string `sigelith-hourglass test vector`;
- `trees`: roots for n = 1, 2, 3, 4, 8, 12 (for n ≤ 3 also all labels as `[d, b, hex]`), node
  count and input length; tag `p0`;
- `proofs`: checks, the proof and its SHA-256 for (n, t) = (4, 8) and (8, 16); tag `p0`;
- `claim_permille`: a table [t, λ, p];
- `chain`: a p0 genesis and two segments (n = 4, t = 8, λ = 4, TEST parameters) with proofs,
  `inputs_digest_1`, an interruption in segment 2 and an example of the Δ_min arithmetic;
- `v1.trees`, `v1.proofs`: the same with the tag `v1`;
- `v1.chain`: a v1 genesis (`operator` = `example.org`) and two segments (n = 4, t = 8, λ = 4, k = 1,
  s_ref = 10 nodes/s, TEST parameters chosen so that §10 gives non-zero numbers), signed with a
  TEST key (secret = SHA-256 of the string `sigelith-hourglass test key`, public by design), with
  the exact signed bytes of segment 1, the record as the prover writes it before signing, the
  arithmetic of §10 (segment 1 slower than s_ref, segment 2 faster) and of §10.1 (segment 2 with
  a one-check prefix).

The vectors are checked by a test that recomputes everything, including an independent recursive
method straight from the graph definition. The reference verifies Ed25519 with the standard
library only; its tests use the vectors of RFC 8032, section 7.1.

## 12. Open in this specification

- The exact theorem for the Fiat-Shamir version (§6), to be confirmed with the papers. The quantum
  security of the Fiat-Shamir version is shown by Blocki, Lee, Zhou (ITC 2021); the margin of the
  v1 parameters against a quantum adversary is not computed (note no. 1).
- k = 20 is reviewed once a year; every record carries the k it was computed with.
- The prover's state file is an implementation detail, not a public format (`state.txt`, format
  `sigelith-hourglass-state-1`: segment number, φ_{j−1}, seed and inputs of the current segment,
  next leaf, label stack, interruptions; next to it an append-only journal of the tree's top
  levels).
- How another operator delivers its records to Sigelith is an interface of the publication, not a
  format of the clock.

## 13. Changes from phase 0

- identifiers and domain separators `v1` (§1);
- genesis: `operator` added, `s_ref_nodes_per_s` instead of `s_self_nodes_per_s` (§7);
- records: `s_ref_nodes_per_s`, `key` and `sig`; the prover writes the record without a key, the
  operator's publisher signs it (§8);
- Δ_min per segment in milliseconds, with k and s_ref of each record and s_eff (§10); proof
  prefixes for a requested age (§10.1); several clocks (§10.2);
- parameters unchanged: n = 32, t = 256, λ = 100.
